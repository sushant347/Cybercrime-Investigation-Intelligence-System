# Legal and regulatory corpus

Primary sources for the statutory-basis module
(`timeline_report_engine/ciis_timeline_report/legal/`). These are public
instruments of Nepali law and policy, kept in the repository so that every
provision the engine cites can be checked against the text it came from rather
than taken on trust.

`manifest.json` is generated by `build_manifest.py` and records, per document,
what it is, what script it is in, whether a machine can read it, and what the
project does with it.

## What this corpus is — and is not — used for

**The engine does not train on this corpus. No model of any kind is fitted to
it.** Five provisions of one Act were transcribed by hand into
`legal/provisions.py`: the section number, the heading as enacted, and the
penalty as written.

The accurate claim is that **the statutory module is grounded in the primary
legislation, and every citation can be verified against the source held here.**
That is a stronger claim than "trained on", because it is checkable — open
`provisions.py` beside the Act and compare.

## What is actually consumed

| Document | Used for |
|---|---|
| `2.1 The Electronic Transactions Act, 2063 (2008).pdf` | Sections 45, 46, 47, 52, 53, 54, 55, 56 — 8 of the Act's 15 offence sections |
| `7.3 The Patent, Design and Trade Mark Act, 2022 (1965).pdf` | Section 19 — illegal use of trade-marks, triggered by brand/logo detection |
| `7.2 The Copyright Act, 2059 (2002).pdf` | Section 27 — infringement, triggered by template-matched artwork |

The Copyright rule is dormant unless an investigator supplies reference logos in
`storage/forensics/logo_templates/<brand>/`: without them the detector reports
keyword and colour matches, which evidence *use of the mark* (trade-mark s.19)
but not *reproduction of the work*.

Everything else is reference material, held for provenance and for work not yet
done. Its presence is not a claim that the engine implements it. Which sections
of the Electronic Transactions Act are deliberately not assessed, and why, is
recorded in `provisions.UNASSESSED_ETA_SECTIONS`.

## The Nepali texts

The corpus contains the Nepali originals of both the Act and the Rules. **They
cannot be machine-extracted.**

Nepali government instruments of this period are typeset in legacy non-Unicode
fonts — here `Preeti` and `PCSNEPALI`. Those render as Devanagari on screen but
the underlying bytes are Latin, so extraction returns nonsense: the Act's own
title comes out as `ljB'tLo sf/f]af/ P]g`.

A transliteration table for Preeti exists. It is deliberately **not** used,
because applying one to statutory text that nobody on this project can
proof-read would produce citations that look correct and are wrong — the exact
failure mode this system is built to avoid everywhere else.

What *is* used from the Nepali material:

- **The Act's title**, `विद्युतीय (इलेक्ट्रोनिक) कारोबार ऐन, २०६३`, taken from
  the gazette copy's filename, which is proper Unicode. Every report names the
  instrument in Nepali as well as English.
- **A standing note in every report** stating that the citations were taken from
  the English text and that the Nepali text is authoritative where the two
  differ.

Section headings therefore appear in English only. Correcting that needs a
Nepali reader to verify a transliteration, not more code.

One document *is* fully readable: the NCSC cyber-security advisory is Unicode
Devanagari (94%), though some conjuncts extract lossily.

## Rendering note

The Markdown and JSON reports carry the Nepali title in full. The PDF does not:
its standard-14 font set covers Latin-1 only and draws Devanagari as
placeholder boxes, which on a legal document reads as corruption. The PDF
substitutes a Latin note pointing back here. Embedding a Devanagari face (Noto
Sans Devanagari, OFL) would fix it properly; falling back to whatever font
happens to be installed would make the same report render differently on
different machines, which an evidentiary artifact must not do.

## Regenerating the manifest

```bash
python samples/legal_corpus/build_manifest.py
```

Run it after adding or replacing a document.

## Provenance caveat

The Nepali texts are authoritative where they differ from the English
translations. The engine transcribes from the English text of the Act, so any
citation should be checked against the Nepali original before it is relied on
in a filing.
